# Decisions

Pinch's settled decisions, newest first. They were made and numbered in the GenUI repository, where Pinch began as the `/pin` route, so the numbers run D58–D67; the GenUI decisions (D1–D57, D56 the handbook and D57 its references among them) and the links to `product.md` don't apply here. Where an entry says "the handbook password", read `ADMIN_PASSWORD`; where it says `PIN_HOSTS` or "GenUI's own host", that host switching is gone: this repository serves Pinch at `/` and nothing else. Code links point at [architecture.md](architecture.md).

Rules themselves live in [design.md](design.md) and [architecture.md](architecture.md); this page only records each choice and its reason. New decisions go at the top, numbered on from D72.

## Settled

- **2026-10-20 — D72 The logo rises and sets with the theme (user request, "do the same for the logo").** The wordmark is drawn twice in one clip, each copy in its theme's own text colour (#3d3d3d in light, #d8d8d8 in dark, the `--foreground` values), and the two swap exactly like the theme switch's sun and moon (D71): the outgoing copy sinks out while the incoming one comes up from below, 700 ms, driven by `dark:` so nothing animates on load. The clip is padded vertically so the "TM" above the lockup is not cut. Assistive tech hears one "Pinch" (the wrapper is the image; the copies are hidden). The two landing pills (logo, theme switch) fade their background over the same 700 ms so they do not snap beside the logo; reduced motion swaps without moving or fading.
- **2026-10-20 — D71 The theme switch animates its icons like a sunrise and sunset (user request).** The sun and moon sit in the same spot, inside a clip the size of the icon, and swap with the `dark:` class on `<html>` (set before first paint), so nothing animates on load: the outgoing icon sinks out of the clip while the incoming one comes up from below, 700 ms, and the same the other way. Vertical motion reads as a rise and a set in both directions, where a spin would run one of them backwards. Tailwind v4 sets `translate` as its own property, so the transition lists it, not `transform`. As with the painting (D70), the theme provider switches with transitions off, so the transition is forced on with `!`; under reduced motion the icons swap without moving.
- **2026-10-20 — D70 The landing painting follows the theme (user request).** Dark mode keeps the dusk painting; light mode shows a night version of the same scene (`landing-night.webp`), laid over the dusk one and faded in over 700 ms when the theme changes (the toggle or the D key). The theme provider switches themes with transitions off, so the fade is forced on with `!` on those two classes only; under reduced motion it swaps without a fade. The glass card follows the theme too: near-black in dark mode, white (90%) with a dark button in light mode, its colours fading with the painting; the folder drawing takes its colours from `--fold` and `--glow-*`. The landing also drops the reserved scrollbar gutter (`html:has([data-landing])`), which showed as a strip beside the painting since the page never scrolls there. The dusk image keeps the preload (dark is the default); the night one loads as soon as the page does.
- **2026-10-20 — D69 The export after an end-to-end test with real references (user request).** Eight real marketing screenshots (WebP, JPEG, PNG, one over the pixel budget, one very tall) with 23 notes (dots, areas, arrows, a keyboard-placed note, an accepted AI suggestion, a deleted note, every source and none) were exported and read blind by a Fable 5.1 agent; a second one audited every marker and crop against the known targets. Positions, text, colours and arrow directions were all correct (168 automatic checks). Fixed: **(1)** a picture with no source now says `Source: not set` (README and `source: null`) and the rules say not to assume it is Ours; **(2)** README claims that were false are corrected (crops can still cut through text; the numbered disc can overlap neighbours); **(3)** crops: dots get a landscape window 60% of the image wide (480px to 1400px), so a small image's crop is at 1:1 and shows whole lines, arrow margins are 30% with a floor of 96px and a 60% aspect floor, crop edges settle only on a word-wide quiet band, and crops are JPEG (a close-up was up to 2.6 MB as PNG); **(4)** a scaled JPEG stays JPEG (a PNG of a photo was 11 MB), and the README and `notes.json` name the file that ships; **(5)** the README says the marked copy is scaled to 1800px and positions are in the pixels of `images/`; `AGENTS.md` is a three-line pointer instead of a copy of the README, `notes.json` drops empty `label`/`note`, the constant `origin: user`, and float noise (fractions to four places); the dead "placed by AI" rule is gone. A second round (blind reader and crop audit, with the same notes) found all 23 notes read correctly with high confidence, and every marker, colour and arrow direction right. **Then (user request) the markers were kept off the text:** a disc's place is now scored by ink as well as edges (`inkShare`: cells unlike the background around them, which sees the inside of large type and filled badges that edge counting missed), counts as clear only at 0.5% coverage instead of 3% (at 3% its rim touched a label's letters), and may go further out (3.4–5.6 radii) when nothing near is clear; an area's number tries all four corners outside the box, not only the top-left; an arrow's shaft is thinner and 80% opaque and its head smaller, so the text it crosses stays readable. **And the contact sheet's numbers (user request):** the sheet used to shrink the 1800px marked copies, so their discs came out a few pixels high; each image is now drawn into its cell from the original with its notes drawn at that size (discs at least 22px across, placed with the same rules, kept out of the corner under the image's number badge), so every note number reads on every tile. Also found and fixed in production: saves after a day's first write failed because Blob's weak ETag was refused by `ifMatch` (the same helper is in the GenUI repo's playground).

images are scaled by area (16 megapixels), tall screenshots fit the stage width and scroll; the desktop-only screen is decided by the device, so 200% zoom keeps working (WCAG 1.4.4, 1.4.10); two tabs warn each other; blocked storage falls back to memory with a banner; the open image survives a reload; a focus-trapped dialog for shortcuts, privacy and the logo, which starts a new batch after an unsaved-work check. **Look:** the source picker is four radio rows with Clear, thumbs icons replace the verdict dots, a TM on the wordmark, muted hover fills on segmented options, ghost buttons and text links, text at 13px and 44px hit areas, Plus for Add more and a restart icon for Start over. **Export:** the number disc is placed off text and off the arrow's line, the README says the spot is the ring, box or arrow ends and to trust the coordinates, and that images over 16 megapixels were scaled. **Server:** 15 placements a visitor (moot now) and at most a third of a day's AI dollars per visitor; Reading saved notes needs `ADMIN_PASSWORD`, which the owner chose not to set; they read the day files in the Vercel Blob dashboard instead. **Later the same day:** the short-name field and its suggestion are gone (the model, export and old sessions still carry a `label` if one exists); the Copy for agent button has no dropdown and no Shift-click batch copy; the "Add a note / area / arrow without the mouse" rows are gone (the `N` key adds the selected tool's mark at the centre); the suggestion hint shows once, with a close button, and never returns once closed or used; the thumbs icons are greyscale; the source options carry icons (house, swords, globe, lightbulb) in a bordered 2×2 grid; the Area tool shows a dashed box; Privacy is a lock icon button.

- **2026-10-19 — D66 Pinch tags saved notes by area with Jev (user request).** After a note is saved, a background step (`after()`, so saving never waits) asks Jev, TypeSafe's yes/no model that already routes the playground, ten questions about the note's words: type, colour, layout, hierarchy, density, copy, components, imagery, motion, accessibility (threshold 0.6; a note can have several areas or none; notes under 12 characters are skipped). Tags sit on the entry in the day document with a hash of the text they describe: an edit drops them at once and re-tags, an unchanged re-send keeps them, and the browser can never set them. Off without `JEV_API_KEY` or with `PIN_TAGS=0`; `PIN_TAG_CALLS_PER_DAY` (2,000) caps calls. Only the note's words go to TypeSafe: no ids, image or source. The owner reads counts with `GET /api/pin/notes?summary=YYYY-MM` behind the handbook password; no page was wanted. Why Jev and not Haiku: it is a classifier and cheap, and tags are only counted. Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D65 Pinch has an arrow (user request, after Scrawl).** A mark can be an arrow from a tail to a head: "move this there", "align this with that". It is read as "this (tail) relates to that (head)" in the README, `notes.json` (`shape: arrow`, pixels with x2, y2), the clipboard summary and the saved-note log. Drawn with Shift-drag, or with the stage's Pin/Arrow switch or the `A` key; a drag under 2% of the image makes nothing. Only the user draws arrows; the AI still places dots and areas. The suggestion prompt knows when the marker is an arrow. Code: `src/lib/pin/model.ts`, `src/components/pin/render.ts`, `pin-app.tsx`.
- **2026-10-19 — D64 Pinch's export reads like a Scrawl bundle (user request; after Scrawl, MIT).** Four ideas borrowed from Kit Langton's [Scrawl](https://github.com/kitlangton/scrawl) (MIT), credited in the code. A reading contract at the top of the README, and the same words in `AGENTS.md` at the zip root: look at the contact sheet first, then each note's crop, the marked copy when the place matters and the original only when the crop lacks detail (each image costs context); don't ask the author to repeat what a note says; refer to notes as "02.3"; an AI-placed note that wasn't checked is an unconfirmed position. `contact-sheet.jpg`: every marked copy in batch order, packed into justified rows (Scrawl's `plan_contact_sheet_rows`, ported with its notice in `sheet.ts`; batches over twelve are planned in chunks), 1600px and about 1.56 megapixels at most, a keycap badge with the image's number on each. Crops that don't cut through text or controls: each edge grows outward, up to 40% of the crop a side and inside the image, until it sits on a quiet band of the image (`settleCrop`, after Scrawl's autocrop; the image is sampled on canvas, and the plain rectangle is kept when it can't be); `notes.json` (`version` 2) reports the crop as drawn. Numbers beside dots: a dot is a small open ring on the point with its number on a disc up and left of it on a short leader, flipped to the side with room near an edge, so the number never covers what the dot marks; an area's number sits just outside its top-left corner when there is room. The on-screen pins are unchanged. Why: the export is read by a model with a context budget and no way to ask, so it should know what to open first, and no picture should hide or cut what a note is about. Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D63 Pinch saves the text of notes, anonymously (user decision).** Every written note's text (what works, what doesn't, its short name, an image's free note) is sent to the server a few seconds after typing stops and when the tab is hidden, and kept in the private Blob store (`pin-notes/text/<day>.json`) for 90 days. Kept with it: the note's and image's random ids, dot or area, who placed it (user or AI), whether an accepted suggestion was kept as is or edited, and the image's source kind. Never kept: images, file names, "made by", links, IP addresses (a salted hash counts new notes per visitor per day for the cap, unlinked to any note). On by default with no opt-out, at the user's request; the landing page said so until the user asked for that sentence to go (D67). Why: to learn how designers judge screens, which the export alone never shows us. Readable only behind the handbook password (`GET /api/pin/notes`). Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D62 Pinch suggests what works and what doesn't (user request).** An empty note shows an AI draft as grey text in each field; Tab in the empty field takes it, typing replaces it. On by default, with a Suggestions switch in the header remembered per browser. A small fast model writes them (`claude-haiku-5-5`, `PIN_SUGGEST_MODEL`), from the whole screen and a close-up of the spot, both marked in magenta so the marker isn't read as design; a sentence about the marker or the crop is dropped. The export marks accepted words "AI suggestion, accepted as is" or "edited by the author". Why Haiku and not Jev: the user asked about combining them; Jev answers yes/no questions about text and can't write a sentence or see an image, so it has no part in drafting (it could tag finished notes by area, offered as a separate step). Own daily cap (`PIN_SUGGEST_*`). Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D61 Pinch images carry their source (user request).** Each image can be marked Ours, Competitor, Other product (a real product outside our space; the user asked for this one) or Concept (a mockup, never shipped), with an optional maker and link. New images take the open image's source, and "Set for all" applies it to the batch. The README and `notes.json` name it, and the README tells the agent how to weigh each: fix or keep our own, take only the principle from anyone else's. Why: the same note means different things on our product and on a competitor's, and an agent can't tell which screenshot is whose.
- **2026-10-19 — D60 The product is called Pinch (user request; renames Pin notes, D58 and D59).** The user asked for the name Pinch. Changed: the header name, page title and link preview, the export's folder and zip (`pinch-<date>`), `tool` in `notes.json`, the README's "Exported from Pinch", comments and these docs; the landing headline is now regular weight. Kept on purpose, so nothing in use breaks: the `/pin` route and `src/*/pin` folders, the `PIN_HOSTS` and `PIN_AI_*` settings, the browser database name `pin-notes` (renaming it would lose saved sessions), the icon path, the AI budget's ledger key, and the live address `pinnotes.vercel.app`. D58 and D59 keep the old name as written. A new address such as `pinch.vercel.app` is added with a domain and a `PIN_HOSTS` change.
- **2026-10-19 — D59 Pin notes is its own free website (user request; closes O7).** The user asked for a standalone site, free and without an account, where anyone uploads a batch of references, tags them and exports everything for their agent. It is a product of its own, not part of GenUI, so GenUI is still not a standalone design tool ([product](product.md#what-genui-is-not)): on the hosts in `PIN_HOSTS` the same deployment serves only Pin notes (`/` is the tool, with its own name, icon, page title and `robots.txt`; every GenUI page answers 404), and on GenUI's own host `/pin` stays unlinked and `noindex`. Why one deployment: one codebase and one AI budget, and the site needs only a domain to go live. Code: [architecture, Deploy](architecture.md#deploy).
- **2026-10-19 — D58 Pin notes: tag a batch of screens, export it for any agent (user request).** A page at `/pin` where a designer adds a batch of screenshots (30 in one session), clicks for a dot or drags for an area on each, and says what works, what doesn't, or both; or writes freely about an image and lets the AI place each point (Claude finds the element and returns its box; the user checks it). The export is one zip any agent can read: the images, a marked copy of each with numbered markers, a crop of every note with its marker drawn in, `notes.json`, and a README that names each note's crop and position in percent and pixels. No account: the session lives in the browser (IndexedDB) and nothing is uploaded except one image and its note when the AI step runs, which keeps nothing. Why: the handbook's references (D57) are one person's, behind a password, and an agent can't tell which words on a screenshot refer to which part; a pin or a box ties them, and a crop shows the model exactly what was meant. It became its own site the same day (D59). Code: [architecture, Repo map](architecture.md#repo-map).
