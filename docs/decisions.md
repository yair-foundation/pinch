# Decisions

Pinch's settled decisions, newest first. They were made and numbered in the GenUI repository, where Pinch began as the `/pin` route, so the numbers run D58–D67; the GenUI decisions (D1–D57, D56 the handbook and D57 its references among them) and the links to `product.md` don't apply here. Where an entry says "the handbook password", read `ADMIN_PASSWORD`; where it says `PIN_HOSTS` or "GenUI's own host", that host switching is gone: this repository serves Pinch at `/` and nothing else. Code links point at [architecture.md](architecture.md).

Rules themselves live in [design.md](design.md) and [architecture.md](architecture.md); this page only records each choice and its reason. New decisions go at the top, numbered on from D75.

## Settled

- **2026-10-20 — D75 Collections, learnings and a rules export, the small version (user request).** The paid idea is "I don't have to explain my taste again", so the small version tests whether people come back to reuse and refine what their notes teach. **Collections** are named and kept in this browser, in their own IndexedDB database (`pinch-collections`) so nothing a saved session depends on changed. A collection holds **batches as their Pinch exports**: the export is already the portable form of a batch, so one reader (`unzip.ts`, `import.ts`) serves three things: opening an export into the session (built as "Import of an export", also the way to move a batch between browsers), importing one into a collection, and opening a kept batch again. A batch is added from the open one ("Add open batch" builds its export) or from a zip; the same notes twice are refused. **One learning per note**, created empty when the batch is added: the rule the note teaches, which the author writes, or the AI drafts. The author approves, edits or rejects it, and marks it **Personal taste** or **This project** (this project by default when the image is Ours). Learnings are grouped by the note's first **topic tag** (D71), not by Jev's areas as first proposed: Jev's tags live on the server for the owner's counts and never reach the browser, and the topic tags are what the author chose. **Drafting** (`/api/pin/learn`) sends only the notes' words, their short name, topics and source, never an image or file name, twelve notes a request, on Claude Opus 5.5 (`PIN_LEARN_MODEL`) at medium effort with the server-side refusal fallback, under its own daily cap like suggestions; it is off without a key, and the author can write every rule by hand. The prompt asks for one sentence that keeps the note's specifics and adds none, since a generic rule ("use clear hierarchy") is worth nothing; quality with the real model is untested here. **Export** zips `design-rules.md` (how to use them, then the rules by scope and topic, numbered R1, R2…, each with its note and close-up), `rules.json` and the close-ups as `evidence/r01.jpg` and on, read from the batch's zip; the approved rules are in it unless unticked. Not built: sync between browsers, picking rules per task, editing a learning's topics. The privacy dialog says what drafting sends. Code: `collections.tsx`, `collections-store.ts`, `src/lib/pin/learnings.ts`, `learn.ts`, `import.ts`, `unzip.ts`, `src/app/api/pin/learn/route.ts`.
- **2026-10-20 — D74 Topic tags: no icons, even gaps, as wide as their labels (user request).** The tags lose their icons (amends D72); a tag that is off is a plain outline with a muted label, and one that is on is filled with its tint, its label in the tint. Each tag is as wide as its label, with no empty space inside, and they wrap with 8px between rows, the same as between tags (the aligned columns of D73 are gone; they stretched short tags). At 28px tall, 8px rows would make the usual 44px hit areas overlap, so a tag's hit area is 36px tall: rows tile without overlap, still over WCAG 2.5.8's 24px. Amends the 44px rule in [design.md](design.md) for these tags only.
- **2026-10-20 — D73 A tidier note editor (user request).** The red "Delete note" button and the "Ctrl Enter done · Esc close" caption below the tags made the end of a note look cluttered. Delete is now a trash icon button beside Done in the note's title row (named "Delete note", with a tooltip), as the image's own trash sits in its title row; the keys moved into Done's tooltip, and the shortcuts dialog still lists them. The tags' heading "About" became "This note is about", which says what the tags are for. The tags sit in columns as wide as their widest tag, three on the wide panel and two on the narrow one, so the rows line up. The export keeps its `About:` line.
- **2026-10-20 — D72 Topic tags are smaller, squarer and coloured (user request, from a reference of tinted status tags).** The About chips of D71 become 28px tags (from 36px pills) with 6px corners, an icon each (palette, grid, quote, pointer, route, accessibility) and a tint each: Visual fuchsia, Layout blue, Copy teal, Interaction violet, Flow orange, Accessibility green. Off, a tag is outlined with its icon in its tint and a muted label; on, it is filled with a light tint (a 15% tint in dark) and its label takes the tint; suggested ones stay dashed. No red, which already means "doesn't work" and delete; teal, orange and green use the 800 shade for text so every label is at least 5.4:1 on its fill in light and 9.6:1 in dark. The weight no longer changes when a tag turns on, so tags don't shift. Rows are 16px apart so the 44px hit areas still tile. Amends three rules in [design.md](design.md): colour as an accent, chips as pills, icons never colour-coded. Code: `TopicPicker`, `TOPIC_TONES`, `TOPIC_ICONS` in `pin-app.tsx`.
- **2026-10-20 — D71 Notes say what they are about (user request).** Each note has six optional topic chips under its fields, **About**: Visual (how it looks: type, colour, icons, imagery), Layout (where things sit and what stands out: spacing, alignment, hierarchy, density), Copy (the words), Interaction (how controls behave: states, feedback, motion), Flow (steps, navigation, what happens next) and Accessibility. Any number can be on, none is needed. Why: an agent reading "I like this heading" can't tell whether the author means its look, its place or its words, and a wrong guess sends the work in the wrong direction. The author picks them rather than a classifier, since a wrong automatic tag adds the ambiguity back; but a suggestion now also returns one or two topics (same Haiku call, no extra cost, it already sees the close-up), shown as dashed chips while its grey text shows and the note has no topics yet, and taken with its words on Tab. Six broad chips, not Jev's ten areas, so tagging stays quick; "UX" was missing from those areas, hence Flow. The export carries them: an `About:` line on each note, counts by topic in the README's first lines, a reading rule (a note about Copy is about the words, not how the text looks; untagged means go by the words), `topics` on each note in `notes.json` with their meanings at the top; Copy for agent adds `about:`. Topics stay in the browser and the export: the saved note log and Jev tagging are unchanged, so what leaves the browser is unchanged. The chips are pills, filled with the primary colour when on (no colour key), 36px tall and 8px apart so their 44px hit areas tile. Code: `src/lib/pin/model.ts` (`TOPICS`), `suggest.ts`, `summary.ts`, `pin-app.tsx` (`TopicPicker`).
- **2026-10-20 — D70 The landing painting follows the theme (user request).** Dark mode keeps the dusk painting; light mode shows a night version of the same scene (`landing-night.webp`), laid over the dusk one and faded in over 700 ms when the theme changes (the toggle or the D key). The theme provider switches themes with transitions off, so the fade is forced on with `!` on those two classes only; under reduced motion it swaps without a fade. The glass card follows the theme too: near-black in dark mode, white (90%) with a dark button in light mode, its colours fading with the painting; the folder drawing takes its colours from `--fold` and `--glow-*`. The landing also drops the reserved scrollbar gutter (`html:has([data-landing])`), which showed as a strip beside the painting since the page never scrolls there. The dusk image keeps the preload (dark is the default); the night one loads as soon as the page does.
- **2026-10-20 — D69 The export after an end-to-end test with real references (user request).** Eight real marketing screenshots (WebP, JPEG, PNG, one over the pixel budget, one very tall) with 23 notes (dots, areas, arrows, a keyboard-placed note, an accepted AI suggestion, a deleted note, every source and none) were exported and read blind by a Fable 5.1 agent; a second one audited every marker and crop against the known targets. Positions, text, colours and arrow directions were all correct (168 automatic checks). Fixed: **(1)** a picture with no source now says `Source: not set` (README and `source: null`) and the rules say not to assume it is Ours; **(2)** README claims that were false are corrected (crops can still cut through text; the numbered disc can overlap neighbours); **(3)** crops: dots get a landscape window 60% of the image wide (480px to 1400px), so a small image's crop is at 1:1 and shows whole lines, arrow margins are 30% with a floor of 96px and a 60% aspect floor, crop edges settle only on a word-wide quiet band, and crops are JPEG (a close-up was up to 2.6 MB as PNG); **(4)** a scaled JPEG stays JPEG (a PNG of a photo was 11 MB), and the README and `notes.json` name the file that ships; **(5)** the README says the marked copy is scaled to 1800px and positions are in the pixels of `images/`; `AGENTS.md` is a three-line pointer instead of a copy of the README, `notes.json` drops empty `label`/`note`, the constant `origin: user`, and float noise (fractions to four places); the dead "placed by AI" rule is gone. A second round (blind reader and crop audit, with the same notes) found all 23 notes read correctly with high confidence, and every marker, colour and arrow direction right. **Not changed, open for a later pass:** numbered discs and arrow lines still sometimes sit on the text they describe, and the contact sheet's note numbers are small on small images. Also found and fixed in production: saves after a day's first write failed because Blob's weak ETag was refused by `ifMatch` (the same helper is in the GenUI repo's playground).
- **2026-10-20 — D68 Pinch after its end-to-end review (user requests).** An independent review (21 findings) was fixed in full, and the owner asked for these product changes the same day. **Removed:** AI placement ("Find these in the image" and "Place notes on N images"; the route, its budget and `PIN_AI_*`/`PIN_MODEL`/`PIN_EFFORT` settings), so only suggestions call Anthropic; the "Or write freely about this image" box (older sessions' overall notes still load and export); the maker and link of a source (amends D61). **Privacy:** the landing footer says images stay in the browser and suggestions send the marked area to Anthropic, with a "How Pinch uses your data" dialog (also in the header) naming Anthropic, TypeSafe, the 90-day note text and the salted IP hash (replaces D67's removal). **Marks:** a Pin / Area / Arrow toolbar (P, R, A), keyboard creation of areas and arrows, a focusable resize handle, `[`/`]` between notes. **Suggestions:** Tab still accepts (D62), Esc or Delete dismisses, the hint is a tooltip, the ghost fades, a wider filter drops sentences about the overlay. **Robustness:** unreadable files keep the session and say why; images are scaled by area (16 megapixels), tall screenshots fit the stage width and scroll; the desktop-only screen is decided by the device, so 200% zoom keeps working (WCAG 1.4.4, 1.4.10); two tabs warn each other; blocked storage falls back to memory with a banner; the open image survives a reload; a focus-trapped dialog for shortcuts, privacy and the logo, which starts a new batch after an unsaved-work check. **Look:** the source picker is four radio rows with Clear, thumbs icons replace the verdict dots, a TM on the wordmark, muted hover fills on segmented options, ghost buttons and text links, text at 13px and 44px hit areas, Plus for Add more and a restart icon for Start over. **Export:** the number disc is placed off text and off the arrow's line, the README says the spot is the ring, box or arrow ends and to trust the coordinates, and that images over 16 megapixels were scaled. **Server:** 15 placements a visitor (moot now) and at most a third of a day's AI dollars per visitor; 6 MB of note text a day and 1 MB per visitor; the visitor is the platform's `x-real-ip`; a same-origin claim with a foreign `Origin` is refused; over-long text is truncated, not rejected. Reading saved notes needs `ADMIN_PASSWORD`, which the owner chose not to set; they read the day files in the Vercel Blob dashboard instead. **Later the same day:** the short-name field and its suggestion are gone (the model, export and old sessions still carry a `label` if one exists); the Copy for agent button has no dropdown and no Shift-click batch copy; the "Add a note / area / arrow without the mouse" rows are gone (the `N` key adds the selected tool's mark at the centre); the suggestion hint shows once, with a close button, and never returns once closed or used; the thumbs icons are greyscale; the source options carry icons (house, swords, globe, lightbulb) in a bordered 2×2 grid; the Area tool shows a dashed box; Privacy is a lock icon button.

- **2026-10-19 — D66 Pinch tags saved notes by area with Jev (user request).** After a note is saved, a background step (`after()`, so saving never waits) asks Jev, TypeSafe's yes/no model that already routes the playground, ten questions about the note's words: type, colour, layout, hierarchy, density, copy, components, imagery, motion, accessibility (threshold 0.6; a note can have several areas or none; notes under 12 characters are skipped). Tags sit on the entry in the day document with a hash of the text they describe: an edit drops them at once and re-tags, an unchanged re-send keeps them, and the browser can never set them. Off without `JEV_API_KEY` or with `PIN_TAGS=0`; `PIN_TAG_CALLS_PER_DAY` (2,000) caps calls. Only the note's words go to TypeSafe: no ids, image or source. The owner reads counts with `GET /api/pin/notes?summary=YYYY-MM` behind the handbook password; no page was wanted. Why Jev and not Haiku: it is a classifier and cheap, and tags are only counted. Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D65 Pinch has an arrow (user request, after Scrawl).** A mark can be an arrow from a tail to a head: "move this there", "align this with that". It is read as "this (tail) relates to that (head)" in the README, `notes.json` (`shape: arrow`, pixels with x2, y2), the clipboard summary and the saved-note log. Drawn with Shift-drag, or with the stage's Pin/Arrow switch or the `A` key; a drag under 2% of the image makes nothing. Only the user draws arrows; the AI still places dots and areas. The suggestion prompt knows when the marker is an arrow. Code: `src/lib/pin/model.ts`, `src/components/pin/render.ts`, `pin-app.tsx`.
- **2026-10-19 — D64 Pinch's export reads like a Scrawl bundle (user request; after Scrawl, MIT).** Four ideas borrowed from Kit Langton's [Scrawl](https://github.com/kitlangton/scrawl) (MIT), credited in the code. A reading contract at the top of the README, and the same words in `AGENTS.md` at the zip root: look at the contact sheet first, then each note's crop, the marked copy when the place matters and the original only when the crop lacks detail (each image costs context); don't ask the author to repeat what a note says; refer to notes as "02.3"; an AI-placed note that wasn't checked is an unconfirmed position. `contact-sheet.jpg`: every marked copy in batch order, packed into justified rows (Scrawl's `plan_contact_sheet_rows`, ported with its notice in `sheet.ts`; batches over twelve are planned in chunks), 1600px and about 1.56 megapixels at most, a keycap badge with the image's number on each. Crops that don't cut through text or controls: each edge grows outward, up to 40% of the crop a side and inside the image, until it sits on a quiet band of the image (`settleCrop`, after Scrawl's autocrop; the image is sampled on canvas, and the plain rectangle is kept when it can't be); `notes.json` (`version` 2) reports the crop as drawn. Numbers beside dots: a dot is a small open ring on the point with its number on a disc up and left of it on a short leader, flipped to the side with room near an edge, so the number never covers what the dot marks; an area's number sits just outside its top-left corner when there is room. The on-screen pins are unchanged. Why: the export is read by a model with a context budget and no way to ask, so it should know what to open first, and no picture should hide or cut what a note is about. Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D63 Pinch saves the text of notes, anonymously (user decision).** Every written note's text (what works, what doesn't, its short name, an image's free note) is sent to the server a few seconds after typing stops and when the tab is hidden, and kept in the private Blob store (`pin-notes/text/<day>.json`) for 90 days. Kept with it: the note's and image's random ids, dot or area, who placed it (user or AI), whether an accepted suggestion was kept as is or edited, and the image's source kind. Never kept: images, file names, "made by", links, IP addresses (a salted hash counts new notes per visitor per day for the cap, unlinked to any note). On by default with no opt-out, at the user's request; the landing page said so until the user asked for that sentence to go (D67). Why: to learn how designers judge screens, which the export alone never shows us. Readable only behind the handbook password (`GET /api/pin/notes`). Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D62 Pinch suggests what works and what doesn't (user request).** An empty note shows an AI draft as grey text in each field; Tab in the empty field takes it, typing replaces it. On by default, with a Suggestions switch in the header remembered per browser. A small fast model writes them (`claude-haiku-5-5`, `PIN_SUGGEST_MODEL`), from the whole screen and a close-up of the spot, both marked in magenta so the marker isn't read as design; a sentence about the marker or the crop is dropped. The export marks accepted words "AI suggestion, accepted as is" or "edited by the author". Why Haiku and not Jev: the user asked about combining them; Jev answers yes/no questions about text and can't write a sentence or see an image, so it has no part in drafting (it could tag finished notes by area, offered as a separate step). Own daily cap (`PIN_SUGGEST_*`). Code: [architecture, Repo map](architecture.md#repo-map).
- **2026-10-19 — D61 Pinch images carry their source (user request).** Each image can be marked Ours, Competitor, Other product (a real product outside our space; the user asked for this one) or Concept (a mockup, never shipped), with an optional maker and link. New images take the open image's source, and "Set for all" applies it to the batch. The README and `notes.json` name it, and the README tells the agent how to weigh each: fix or keep our own, take only the principle from anyone else's. Why: the same note means different things on our product and on a competitor's, and an agent can't tell which screenshot is whose.
- **2026-10-19 — D60 The product is called Pinch (user request; renames Pin notes, D58 and D59).** The user asked for the name Pinch. Changed: the header name, page title and link preview, the export's folder and zip (`pinch-<date>`), `tool` in `notes.json`, the README's "Exported from Pinch", comments and these docs; the landing headline is now regular weight. Kept on purpose, so nothing in use breaks: the `/pin` route and `src/*/pin` folders, the `PIN_HOSTS` and `PIN_AI_*` settings, the browser database name `pin-notes` (renaming it would lose saved sessions), the icon path, the AI budget's ledger key, and the live address `pinnotes.vercel.app`. D58 and D59 keep the old name as written. A new address such as `pinch.vercel.app` is added with a domain and a `PIN_HOSTS` change.
- **2026-10-19 — D59 Pin notes is its own free website (user request; closes O7).** The user asked for a standalone site, free and without an account, where anyone uploads a batch of references, tags them and exports everything for their agent. It is a product of its own, not part of GenUI, so GenUI is still not a standalone design tool ([product](product.md#what-genui-is-not)): on the hosts in `PIN_HOSTS` the same deployment serves only Pin notes (`/` is the tool, with its own name, icon, page title and `robots.txt`; every GenUI page answers 404), and on GenUI's own host `/pin` stays unlinked and `noindex`. Why one deployment: one codebase and one AI budget, and the site needs only a domain to go live. Code: [architecture, Deploy](architecture.md#deploy).
- **2026-10-19 — D58 Pin notes: tag a batch of screens, export it for any agent (user request).** A page at `/pin` where a designer adds a batch of screenshots (30 in one session), clicks for a dot or drags for an area on each, and says what works, what doesn't, or both; or writes freely about an image and lets the AI place each point (Claude finds the element and returns its box; the user checks it). The export is one zip any agent can read: the images, a marked copy of each with numbered markers, a crop of every note with its marker drawn in, `notes.json`, and a README that names each note's crop and position in percent and pixels. No account: the session lives in the browser (IndexedDB) and nothing is uploaded except one image and its note when the AI step runs, which keeps nothing. Why: the handbook's references (D57) are one person's, behind a password, and an agent can't tell which words on a screenshot refer to which part; a pin or a box ties them, and a crop shows the model exactly what was meant. It became its own site the same day (D59). Code: [architecture, Repo map](architecture.md#repo-map).
